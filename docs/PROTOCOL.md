# luo mic 通信协议 v1

本文档是 **唯一权威** 的协议定义。Android 端、Windows 端（Java）、Windows 端（Python）
与测试工具必须严格遵守本文件，任何一端改动都要同步另外两端。

- 传输层：UDP（发现） + TCP（控制 / 音频）
- 字节序：**大端序（Big-Endian / 网络序）**
- 端口：
  - `47777/udp` —— 设备发现（固定端口，手机与电脑都用它）
  - `47778/tcp` —— 控制通道
  - `47779/tcp` —— 音频通道
- 电脑 = 服务端（Server），手机 = 客户端（Client）。手机主动发起全部 TCP 连接。

---

## 1. 设备发现（UDP，端口 47777）

所有报文都是**纯 ASCII 单行文本**，必须以 `\n` 结尾，长度 < 512 字节。

| 方向 | 报文 | 说明 |
| --- | --- | --- |
| 电脑 → 广播 | `LUOMIC/1 DISCOVER` | 每 2 秒广播一次，告诉局域网里的手机“我在这里” |
| 手机 → 广播 | `LUOMIC/1 PROBE` | 手机找不到服务器时每 2 秒广播一次，请求电脑立刻回应 |
| 电脑 → 单播 | `LUOMIC/1 HERE <name_b64> <ctrl_port> <audio_port>` | 电脑回给手机的应答 |

- 广播地址：`255.255.255.255`，并同时向每个网段的定向广播地址（例如 `192.168.1.255`）发送，兼容部分路由器丢弃受限广播的情况。
- `name_b64`：电脑名称（UTF-8），Base64 编码，不含 `=` 填充，便于携带中文名。
- 电脑把应答**单播**回发送方 IP 的 `47777` 端口（不是 source port）。
- 手机收到 `HERE` 后解析出电脑 IP 与端口，立刻尝试 TCP 连接，并缓存该地址用于自动重连。

示例：

```
LUOMIC/1 DISCOVER
LUOMIC/1 PROBE
LUOMIC/1 HERE WVMtUEM= 47778 47779
```

## 2. 控制通道（TCP，端口 47778）

连接建立后，双方交换 **一行一条 JSON**（UTF-8，`\n` 结尾）的报文。

### 2.1 电脑 → 手机

连接建立后电脑**先发** `HELLO`：

```json
{"t":"HELLO","v":1,"name":"DESKTOP-ABC","audio_port":47779,
 "codec":"pcm_s16le","rate":48000,"channels":1,"frame_ms":20}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 电脑名，手机界面显示 |
| `audio_port` | 音频通道 TCP 端口 |
| `codec` | 固定 `pcm_s16le`（16 位有符号小端线性 PCM） |
| `rate` | 采样率，48000 或 16000 |
| `channels` | 声道数，固定 1（单声道） |
| `frame_ms` | 每帧时长，10 / 20（毫秒） |

手机接受后回 `HELLO`。随后电脑发送：

```json
{"t":"START"}
{"t":"STOP"}
{"t":"PING","ts":1234567}
```

- `START`：请求手机开始推流（电脑已打开音频输出设备）。
- `STOP`：请求手机停止推流（电脑关闭了输出设备或程序退出），手机保持控制连接。
- `PING`：心跳，每 2 秒一次。

### 2.2 手机 → 电脑

```json
{"t":"HELLO","v":1,"device":"Pixel 6","android":33,
 "codec":"pcm_s16le","rate":48000,"channels":1,"frame_ms":20}
{"t":"PONG","ts":1234567}
{"t":"STAT","fps":50,"kbps":768,"db":-41}
{"t":"BYE"}
```

- `PONG` 必须原样回填 `PING` 的 `ts`，电脑据此计算 RTT（界面显示延迟）。
- `STAT` 每 2 秒上报一次：`fps` 每秒帧数、`kbps` 码率、`db` 输入电平（dBFS，可为负）。
- `BYE`：手机主动断开前发送。
- 未知字段一律忽略（向前兼容）。

### 2.3 连接与自动重连状态机

```
手机启动
  ├─ 读取上次服务器地址缓存 ──► 有缓存则先直连（超时 3 秒）
  │        └─ 失败 ──► 进入“扫描发现”
  └─ 进入“扫描发现”
           ├─ 监听/主动 PROBE，收到 HERE ──► 记录地址并连接
           └─ 连接成功 ──► 等待 HELLO / START
                    ├─ 收到 START ──► 采集麦克风并推流
                    ├─ 心跳超时（12 秒无任何报文）或 socket 出错 ──► 回到“扫描发现”，指数退避重试
                    └─ 收到 STOP ──► 停止推流，保持连接
```

电脑端同样会自动接受任意新连接：若已有手机会话，新的连接会顶掉旧会话（同一时间只服务一台手机）。

## 3. 音频通道（TCP，端口 47779）

### 3.1 握手

手机连上音频端口后立刻发送 **32 字节**握手头（明文，非加密）：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | `reserved`，填 0 |
| 4 | 8 | `session`，与控制通道 JSON 里约定的随机 64 位会话号（可为 0） |
| 12 | 4 | `rate`，采样率（大端 int32） |
| 16 | 4 | `channels`（大端 int32） |
| 20 | 4 | `frame_ms`（大端 int32） |
| 24 | 8 | 保留，填 0 |

### 3.2 音频帧

握手之后是一条连续的帧流，每帧 = **4 字节长度前缀（大端 uint32） + PCM 数据**：

```
offset size  field
0      4     pcm_len 该帧 PCM 字节数（大端 uint32）
4      N     pcm     16 位小端有符号线性 PCM，单声道
```

- 一帧 = `frame_ms` 毫秒音频，默认 20 ms @ 48 kHz = 1920 字节 PCM。
- `pcm_len` 合法范围 `2 .. 8192`，超出范围视为协议错误，接收端直接断开该连接。
- 用长度前缀而不是魔数同步，接收端可以严格按长度读取，永远不会错位。
- 手机必须按实时节奏发送（不要突发补帧）；`TCP_NODELAY` 必须开启。
- 电脑侧维护抖动缓冲（目标 3 帧 ≈ 60 ms，上限 1 秒），空缓冲时补静音，溢出时丢弃最旧帧。

- 一帧 = `frame_ms` 毫秒音频，默认 20 ms @ 48 kHz = 1920 字节 PCM。
- 手机必须按实时节奏发送（不要突发补帧）；`TCP_NODELAY` 必须开启。
- 电脑侧维护抖动缓冲（目标 3 帧 ≈ 60 ms，上限 1 秒），序号跳跃/回绕时自动重整。

### 3.3 带宽

| 采样率 | 帧长 | 码率 |
| --- | --- | --- |
| 48000 Hz | 20 ms | 768 kbps（约 96 KB/s） |
| 16000 Hz | 20 ms | 256 kbps（约 32 KB/s） |

普通 Wi-Fi 完全够用；网络较差时把手机端采样率切到 16 kHz 可显著降低丢包。

## 4. 端口与防火墙

Windows 首次运行需要放行：

```
netsh advfirewall firewall add rule name="luo mic UDP 47777" dir=in action=allow protocol=UDP localport=47777
netsh advfirewall firewall add rule name="luo mic TCP 47778-47780" dir=in action=allow protocol=TCP localport=47778-47780
```

程序内提供“一键放行防火墙”按钮（会弹出 UAC 提权）。
